# Commercial Battery Assessment Funnel — Test Plan & Results

Companion to `docs/08-commercial-battery-assessment-funnel.md` (design) and
`docs/08a-bess3-bess4-facts.md` (sourced facts). Records what was actually
run this session and what it found — not a description of intent.

## Method

All tests use Playwright/Chromium against a local rebuild of this exact
commit, served on `localhost`. A local, disposable Node HTTP server
(`/lead`, `/received`, `/control/fail-next`) stands in for HighLevel — this
is the "safe local/intercepted CRM destination" the brief requires; nothing
is sent to any real or third-party endpoint. The site's own submission
adapter hook (`window.OHE_BESS_SUBMIT_ADAPTER`) is what makes this
possible without touching production code — see §8 of the design doc.

Test scripts are not committed to the repo (they're throwaway harness
code, not part of the shipped site) — this document is the durable record
of what they proved.

(plus two extra non-allowlisted params, `session_id` and `fbp`, added to
prove discard behaviour).

Pathway completed: commercial/business premises → owner/director →
$20,000–$50,000 quarterly bill → no existing battery → existing solar →
ASAP timeframe → Parramatta NSW 2150 → full contact details → consent

## 3. Verification pass (Phase 4)

- **Viewport/overflow**: 320px, 375px, 390px, 430px, 1280px — zero
  horizontal overflow at any width (`scrollWidth - clientWidth <= 1px`).
  Screenshots taken and visually reviewed — layout matches the existing
  design system, radio-card selection states render correctly, the sticky
  trust panel behaves sensibly on desktop and stacks cleanly on mobile.
- **Keyboard-only navigation**: confirmed Tab reaches the first site-type
  radio card, Space selects it, native arrow-key behaviour moves within the
  radio group, and focus stays on a visible/enabled control throughout
  (never lands on something hidden by the conditional-reveal logic).
- **Structural accessibility**: every `<fieldset>` has a `<legend>`, every
  visible input has an associated `<label>`, the status region
  (`#bessFormStatus`) carries `aria-live="polite"`, every `.error-msg`
  carries `role="alert"`, and the submit button is not reachable at all
  before a site type is chosen (so an empty/premature submission is
  structurally impossible, not just validated after the fact).
  **Limitation**: no automated colour-contrast or full WCAG audit was run —
  no axe-core or equivalent tool is available in this sandbox. This is a
  gap, not a pass; a real automated a11y scan (or manual screen-reader pass
  with NVDA/VoiceOver) is recommended before paid traffic, same as the
  sitewide WebKit gap already documented elsewhere in this repo.
- **Sitewide regression**: `scripts/qa-static-checks.js` (51 built files)
  and `scripts/qa-playwright.js` (full interaction suite) both pass clean
  after this change — no console errors, no broken links/alt text, no
  regression to any existing page, form, or the mobile nav.

**14/14 assertions passed** (excluding the disclosed a11y-tooling gap).

## 4. Red-team pass (Phase 5)

| Attack/failure mode attempted | Result |
|---|---|
| Misleading eligibility claim | Page explicitly states this is "a preliminary check, not a final eligibility decision"; every classification label ends in `_review_required`/`_review`/`_scope`, never `eligible` — **no finding** |
| No CRM adapter configured (the real production default) | Shows the same honest "not connected yet" notice used sitewide — **confirmed, not assumed**: tested with zero adapter injected, verified no redirect, no fake success wording, no conversion event |
| Adapter configured but returns `{ok:false}` explicitly (not just a thrown error) | Handled identically to a network failure — no redirect, no conversion, answers preserved — **no finding** |
| Lost attribution | Covered by acceptance test #1/#2 — **no finding** |
| PII entering analytics | Covered by acceptance test #8 — **no finding** |
| Hidden-branch field leakage | Covered by acceptance test #4 and the BESS3/BESS4 routing repeats (each payload's opposite-branch fields are `null`) — **no finding** |
| False/duplicate conversion events | Covered by acceptance test #10/#12/#12b — **no finding** |
| Direct thank-you-page conversion inflation | Covered by #12b (fresh context, direct load, zero conversions) — **no finding** |
| Double submission | Triple rapid-click sent exactly one request — **no finding** |
| Mobile obstruction | Covered by the viewport pass — **no finding** |
| Keyboard/screen-reader barriers | Covered by the keyboard/structural pass, with the axe-core gap disclosed above — **partial**: basic structure confirmed, full WCAG scan not possible in this sandbox |
| Consent pre-ticked or bypassable | Confirmed unchecked by default; submission blocked with consent unchecked — **no finding** |
| XSS via reflected form values | Injected `<img src=x onerror=alert(1)>` as a name value through the full submit path — no dialog fired, no unescaped `innerHTML` interpolation exists anywhere in the new code — **no finding** |
| Unrelated repository regressions | Sitewide static + Playwright QA both pass — **no finding** |

**10/10 red-team assertions passed; one disclosed tooling gap (no automated
WCAG/contrast scan available).**
